# 编辑器一键去水印并添加深巷水印

入口：`/ops-7q4m/editor`，标题/摘要下方的「一键去水印并加深巷水印」。

## 使用

1. 保存草稿，通过原有按钮或 Blob 助手将图片导入本地原图目录。
2. 首次配置水印模板：上传不超过 1 MB 的透明 PNG，或者在「水印模板与参数」选择文章样图，填写区域百分比，提取黄色文字模板。模板预览应只包含水印，不包含正文或背景。
3. 确认图片处理权限，选择处理方式。黄色不透明文字使用「笔画掩膜修补」。只有已知真实叠加颜色/Alpha 参数时才使用反向混合；参数里的不透明度与透明度相反。
4. 点击「一键去水印并加深巷水印」，逐张串行处理：可靠匹配旧水印并修补后，再添加右下角白色「深巷」文字和橙色小点，透明度 30%（179/255 不透明度），无底色胶囊。结果在右侧展示候选正文，并提供逐张原图/结果对比、跳过或失败原因。未可靠匹配的图片既不去水印，也不添加新水印。
5. 检查原始分辨率结果后点击「确认效果并应用到正文」，再手动保存草稿或发布更新。放弃替换不改变正文。处理期间编辑正文会令候选预览失效，不覆盖新修改。

## 算法与限制

- 使用现有 sharp + Node Worker，不新增 Python/OpenCV、大模型或 GPU 依赖。
- 色度投影/灰度投影 + 归一化相关模板匹配；相对宽度附近五个尺度（85%、92.5%、100%、107.5%、115%），先缩小搜索再原始分辨率校验。默认只搜索右下角。角度变化、样式变化或明显尺寸变化需重新标定。
- 每图处理一个可靠匹配。未匹配或有竞争位置则跳过，不冒充已去水印。匹配分数不是成功概率，也不能证明修补质量。
- 半透明模式按像素反向 Alpha 混合；高不透明度或越界像素回退修补。
- 不透明模式按字形扩展掩膜，使用邻域边界传播与调和迭代修补。这不是 OpenCV Telea 或生成式模型，不能恢复被遮挡的真实文字/面部/纹理，可能产生拉丝或模糊，需要人工预览。
- 保留图像显示尺寸、比例与旧水印修补区域、右下角平台水印区域以外的像素；输出 PNG。「深巷」采用内置字形轮廓，不依赖 Linux 系统中文字体，也不需要联网渲染。旧模板仍可复用，原水印 Alpha 参数不影响平台水印的透明度。
- 原图至多 8 MB / 1200 万像素，仅静态 PNG、JPEG、WebP；每篇最多 100 个图片标签，重复地址只处理一次。结果大于 8 MB 时失败，不偷偷降低质量。
- 单进程同一时间只运行一个图片修复 Worker，单图限时 45 秒、Worker JS 堆 192 MB；原生图像内存仍计入进程总内存，这不是总 RSS 上限。浏览器串行调用并支持停止。
- 只接受当前文章原图的严格哈希路径。外链/Blob 先导入；已处理本地图片和 OSS 图片跳过，不重新下载或重复加工程效果。
- 校准黄色模板只适合颜色稳定且区域内没有其他黄色内容的图片，不能从单张有背景截图推断真实 Alpha。

## 存储和部署

- `data/watermark-templates/default.json` 保存服务器的默认模板和参数；仅通过管理员 API 读写，不进入 Git。可通过 `WATERMARK_TEMPLATE_DIR` 改变目录（测试使用隔离临时目录）。
- 输出保存在 `public/article-images/{articleId}/{24位哈希}.png`；`data/watermark-manifests/{articleId}/{24位哈希}.json` 记录来源、参数和输入/输出/模板哈希，以及平台水印文字、透明度和区域（version 2），不放在公开目录。它们和原图均不进入 Git。
- 新增动态图片路由 `/article-images/{articleId}/{filename}`，新图片生成后无需重启即可预览；manifest 不在该路由的允许列表中。
- 文章 API 不因处理而保存或发布，不执行 OSS 上传。确认后继续沿用原有手动保存、发布、远端同步流程。
- 部署需包含 `scripts/watermark-engine.mjs`、`scripts/watermark-worker.mjs` 和 `scripts/shenxiang-watermark.mjs`。服务器无需新依赖；同步代码后正常构建/重启。默认模板不随 Git 同步，请在目标服务器编辑器重新提取或上传。
- 已处理的本地图片和已有 OSS 图片不会自动补加水印。需要重新生成时应从对应原图开始，检查预览后替换；不要在旧结果上重复叠加或为补水印自动下载 OSS 图片。

## 验证

`node --test tests/watermarks.test.mjs` 验证算法、原图/非掩膜区域保留、无水印跳过和参数拒绝。

`npm run build && node --test tests/watermarks-runtime.test.mjs` 在隔离数据库运行真实 HTTP 测试，覆盖鉴权、跨站、路径、数量限制、原图不变、即时图片访问、manifest 与串行资源保护。

`WATERMARK_UI_REVIEW=1 node tests/watermarks-runtime.test.mjs` 可临时保留测试编辑器，检查预览/确认交互；不要加 `--test`，以便终端输入能传给测试进程。结束时回终端按回车，清理仅本次生成的测试数据。
