# 编辑器一键去水印并添加深巷水印

入口：`/ops-7q4m/editor`，标题/摘要下方的「一键去水印并加深巷水印」。

水印处理为可选功能，不是发布或远端同步的前置条件。已导入当前文章的原图可以直接发布；点击远端同步时，系统上传正文实际引用的原图或处理图到 OSS，不自动修改图片。只有需要去除／添加水印时才执行以下步骤。

## 使用

1. 保存草稿，通过原有按钮或 Blob 助手将图片导入本地原图目录。
2. 首次配置水印模板：上传不超过 1 MB 的透明 PNG，或者在「水印模板与参数」选择「提取颜色」（黄色／黑色／黄色＋黑色描边）、文章样图，填写区域百分比，再点击对应颜色的提取按钮。默认黄色；已保存模板会恢复提取颜色及描边检测范围。切换颜色或范围本身不会替换模板或正文，必须重新提取，提取失败会保留原模板。模板预览应只包含水印，不包含正文或背景。
3. 确认图片处理权限，选择处理方式。黄色不透明文字使用「笔画掩膜修补」。只有已知真实叠加颜色/Alpha 参数时才使用反向混合；参数里的不透明度与透明度相反。
4. 点击「一键去水印并加深巷水印」，逐张串行处理：可靠匹配旧水印并修补后，再添加右下角白色「深巷」文字和橙色小点，透明度 30%（179/255 不透明度），无底色胶囊。编辑器默认勾选「超大结果压缩」：仅在最终 PNG 超过 8 MB 时转为同尺寸高质量 JPEG／WebP，逐张结果会注明有损格式、质量参数和尺寸。可取消勾选以坚持无损 PNG。结果在右侧展示候选正文，并提供逐张原图/结果对比、跳过或失败原因。未可靠匹配的图片既不去水印，也不添加新水印。
5. 检查原始分辨率结果后点击「确认效果并应用到正文」，再手动保存草稿或发布更新。放弃替换不改变正文。处理期间编辑正文会令候选预览失效，不覆盖新修改。

### 黄字、黑描边及倾斜多行水印

选择「黄色＋黑色描边」，用选区包含完整多行文字和黑色边缘，留少量空白，不要只框黄字的一部分。「描边检测范围」按样图原尺寸计算，默认 4 像素，可设 1–12 的整数；只收集黄字附近的深色近中性像素，不是把整块选区涂黑。模板预览应同时出现黄字和黑边，不应混入头发、阴影或正文。

新联合模板默认「底部区域（含居中水印）」搜索、「笔画掩膜修补」及 1 像素笔画外扩，不支持半透明反向混合。原有黄色、黑色模板默认参数不变，也可以手动选择底部搜索。倾斜样图可提取为同样倾斜的模板，但没有旋转搜索；目标水印角度或布局改变时需要重新提取。调整描边范围后需重新提取模板。先检查模板，再处理并查看原图/结果对比，确认没有残边或误伤后才应用正文。

## 算法与限制

- 使用现有 sharp + Node Worker，不新增 Python/OpenCV、大模型或 GPU 依赖。
- 色度投影/灰度投影 + 归一化相关模板匹配；相对宽度附近五个尺度（85%、92.5%、100%、107.5%、115%），先缩小搜索再原始分辨率校验。搜索选项为右下角、底部区域（全宽、下方 40%）及整张图片。普通模板默认只搜索右下角，黄色＋黑色描边模板默认搜索底部。角度变化、样式变化或明显尺寸变化需重新标定。
- 每图处理一个可靠匹配。未匹配或有竞争位置则跳过，不冒充已去水印。匹配分数不是成功概率，也不能证明修补质量。
- 半透明模式按像素反向 Alpha 混合；高不透明度或越界像素回退修补。
- 不透明模式按字形扩展掩膜，使用邻域边界传播与调和迭代修补。这不是 OpenCV Telea 或生成式模型，不能恢复被遮挡的真实文字/面部/纹理，可能产生拉丝或模糊，需要人工预览。
- 保留图像显示尺寸与比例；无损 PNG 保留旧水印修补区域、右下角平台水印区域以外的像素。超限且启用压缩时，JPEG／WebP 有损编码会影响整张成品的像素，必须检查细节，不能承诺像素级无损；原始文件不变。「深巷」采用内置字形轮廓，不依赖 Linux 系统中文字体，也不需要联网渲染。旧模板仍可复用，原水印 Alpha 参数不影响平台水印的透明度。
- 原图至多 8 MB / 4000 万像素，仅静态 PNG、JPEG、WebP；模板提取与后续修复使用同一输入像素上限。每篇最多 100 个图片标签，重复地址只处理一次。成品与 OSS 上传仍至多 8 MB，不放宽远端文件限制。
- 修补与加水印完成后才进行最终编码，避免中间 PNG 超限而提前失败或重复有损编码。最终 PNG 不超限则保持原格式；超限且 `settings.allowLossyOutput: true` 时，不透明成品尝试 JPEG（4:4:4）、含透明像素的成品尝试 WebP（Alpha 质量 100），质量依次为 92、86、80，选择首个满足 8 MB 的结果。最多三次，不缩尺寸，不无限降低质量；仍超限则明确失败。未提供或关闭该选项的接口请求仍保持严格无损模式。图片过长超过编码器边长限制时提示缩小后重导，不丢弃透明通道。
- 模板提取先按 EXIF 显示方向定位选区，再在图像管线中裁剪，不把整张大图转换成 JavaScript RGBA 数组。选区超过 100 万像素时，仅等比例缩小识别模板；水印相对宽度仍按原始选区占原图的比例计算。透明 PNG 模板仍限制为 1 MB / 100 万像素，过少或无法辨认的笔画会安全拒绝并保留旧模板。
- 原始分辨率匹配复查只为候选区域及附近搜索范围分配浮点数组，避免大图的额外全图副本；输出仍保留原图显示尺寸。4000 万像素原图的单份 RGBA 数据约 160 MB，不能将输入限制理解为总内存上限。
- 单进程同一时间只运行一个图片修复 Worker，单图限时 45 秒、Worker JS 堆 192 MB；原生图像内存仍计入进程总内存，这不是总 RSS 上限。浏览器串行调用并支持停止。
- 只接受当前文章原图的严格哈希路径。外链/Blob 先导入；已处理本地图片和 OSS 图片跳过，不重新下载或重复加工程效果。
- 校准黄色模板只适合颜色稳定且区域内没有其他黄色内容的图片，不能从单张有背景截图推断真实 Alpha。
- 黑色模板提取使用保守的暗色、低色差条件（RGB 最大值不超过 95、通道差不超过 35），适合浅背景上的黑色／深灰字，不是文字语义识别。请紧贴水印框选并避开头发、阴影及正文黑字；浅灰半透明笔画、复杂暗背景可能漏选或混入背景。纯黑区域、透明区域、过少或占满选区的候选像素会被拒绝。提取后默认使用笔画掩膜修补，必须检查模板和处理预览。
- 黄色＋黑色描边模板先识别黄字，再保守采集给定半径内的深色近中性描边；定位使用黄字核心，修补使用黄字与描边的联合掩膜。黑色背景不会自动全选，但黄字周围的暗纹理仍可能误入，过满的模板会拒绝。该方案是颜色与局部距离规则，不是文字识别或恢复被遮挡细节。
- 模板接口 `action: "calibrate"` 接受 `color: "yellow" | "black" | "yellow-outline"`，省略时保持黄色兼容；其他值拒绝。可选 `outlineRadius` 为 1–12 的整数，省略为 4，不合法则返回 422 并保留旧模板。联合模板保存该字段及 `extractionColor: "yellow-outline"`；其 `mode` 只能为 `inpaint`。`settings.search` 新增 `bottom`，旧模板仍可使用。仍只保存一个服务器默认模板，新提取成功后替换默认模板，不自动建立多个颜色模板库。

## 存储和部署

- `data/watermark-templates/default.json` 保存服务器的默认模板和参数；仅通过管理员 API 读写，不进入 Git。可通过 `WATERMARK_TEMPLATE_DIR` 改变目录（测试使用隔离临时目录）。
- 输出保存在 `public/article-images/{articleId}/{24位哈希}.{png|jpg|webp}`，扩展名与实际编码一致；`data/watermark-manifests/{articleId}/{24位哈希}.json` 记录来源、参数和输入/输出/模板哈希，以及平台水印文字、透明度和区域（version 2）。新增 `output` 字段记录格式、字节数、宽高、是否有损及质量参数，不放在公开目录。它们和原图均不进入 Git。
- 新增动态图片路由 `/article-images/{articleId}/{filename}`，新图片生成后无需重启即可预览；manifest 不在该路由的允许列表中。
- 文章 API 不因处理而保存或发布，不执行 OSS 上传。确认后继续沿用原有手动保存、发布、远端同步流程。
- 部署需包含 `scripts/watermark-engine.mjs`、`scripts/watermark-worker.mjs` 和 `scripts/shenxiang-watermark.mjs`。服务器无需新依赖；同步代码后正常构建/重启。默认模板不随 Git 同步，请在目标服务器编辑器重新提取或上传。
- 已处理的本地图片和已有 OSS 图片不会自动补加水印。需要重新生成时应从对应原图开始，检查预览后替换；不要在旧结果上重复叠加或为补水印自动下载 OSS 图片。

## 验证

`node --test tests/watermarks.test.mjs` 验证算法、原图/非掩膜区域保留、无水印跳过和参数拒绝。

`node --test tests/watermark-large-images.test.mjs` 使用合成大图验证高分辨率提取、模板缩放、EXIF 方向和像素上限；不读取或修改真实文章图片。

`node --test tests/watermark-output.test.mjs` 验证超大成品的 JPEG／WebP 压缩、透明通道、原尺寸保留、严格无损模式与小图 PNG 兼容。

`node --test tests/watermark-outline.test.mjs` 使用合成的多行倾斜水印验证黄字／黑描边联合模板、底部搜索、描边范围限制、旧模板兼容及非掩膜区域像素保留，不处理真实文章图片。

`npm run build && node --test tests/watermarks-runtime.test.mjs` 在隔离数据库运行真实 HTTP 测试，覆盖鉴权、跨站、路径、数量限制、原图不变、即时图片访问、manifest 与串行资源保护。

`WATERMARK_UI_REVIEW=1 node tests/watermarks-runtime.test.mjs` 可临时保留测试编辑器，检查预览/确认交互；不要加 `--test`，以便终端输入能传给测试进程。结束时回终端按回车，清理仅本次生成的测试数据。
